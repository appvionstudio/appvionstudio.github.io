Case study · Data-heavy utility

Four thousand rows that still scroll at sixty frames.

Attendance software is easy at fifty students and breaks at four thousand. This one was built for the second number from the beginning.

In short

Attendance Suite is an offline-first Android attendance system for universities, academies and institutes, built with Jetpack Compose, MVVM and Firestore. Attendance can be marked present, absent or late with no connection, and updates are conflict-safe using unique identifiers and timestamp checks so two devices marking the same session cannot corrupt each other.

Large rosters are paged rather than loaded, so a four-thousand-row list stays smooth on mid-range hardware. Sync success sits at roughly 99 percent on low-bandwidth connections.

How it works, screen by screen.

Where attendance systems fall over.

Three failures repeat across every institution. The list is loaded in one request, so it stutters the moment enrolment grows. The app requires a connection, so it is useless in the rooms where teaching actually happens. And two people marking the same session overwrite each other, so the record is quietly wrong.

None of these show up in a demo with thirty students on office wifi. All of them show up in week three of a real term.

Decisions that shaped it.

Paging 3 instead of loading the roster

Rows are fetched in pages as the list scrolls, so memory stays flat regardless of enrolment and the list holds sixty frames a second on the mid-range devices institutions actually buy.

Conflict-safe writes, so two markers cannot corrupt a session

Each attendance record carries a unique identifier and a timestamp, and updates are checked against both. Two teachers marking the same session produce a resolvable result rather than a last-write-wins mess nobody notices until an audit.

Exceptions surfaced ahead of the routine

A coordinator does not need to see the four thousand students who were present. They need the late marks, the duplicates, and the students below the attendance threshold. Those are grouped so they are cleared in one pass rather than found by scrolling.

Security hardened where the data actually sits

Strict Firestore rules with user-level validation, composite indexes for the queries that matter, App Check and Play Integrity, and Crashlytics triage with ANR prevention. Attendance is a record that affects whether someone sits an exam, so it is treated as one.

What it changes for an institution.

  • Scale stops being a problem. The system behaves the same at four thousand records as at forty.
  • Marking happens in the room. No connection required, so the paper fallback disappears and with it the transcription errors.
  • The record can be defended. Conflict-safe updates and strict rules mean an attendance figure holds up when a student disputes it.
  • Reporting is in the product. Departmental figures and below-threshold students are available without an export-to-spreadsheet step.
